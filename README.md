# 古船模型帆索校准 · 材料批次召回

运行：

```bash
npm start
```

访问 `http://localhost:3038`。数据原子写入 `data/model-rigging-calibration.json`，重启后仍在。

## 功能

- 原有流程保留：模型建档、状态筛选/搜索、状态推进、追加备注、帆索索位任务。
- **批次登记**：帆索材料按批次登记（编号、材料、供应商、到货日期）。
- **索位批次与依赖**：每条索位登记使用批次，并可勾选本模型内的前置索位（后续依赖关系）。
- **批次召回**（仅质量管理员）：批次异常后一键召回，系统自动计算影响范围——
  直接使用该批次的索位，以及通过依赖链反向追溯到的所有后续依赖索位；
  页面按模型列出受影响模型、索位和依赖项。
- **冻结（支持多活动召回）**：受影响模型立即冻结（状态置“已冻结”），校准、状态推进与交付全部拒绝；
  冻结期备注仍可追加。同一模型可被多个批次的活动召回同时冻结——
  模型持有活动召回 ID 列表，仅首个召回保存冻结前环节；完成/撤销其中一个只摘掉该召回，
  只要还有其他活动召回，冻结与其他召回的换料复校进度就原样保留；
  所有活动召回全部结束后才真正解冻并恢复冻结前所处环节。
- **换料复校清单**：每个受影响索位一项（直接索位=换料，依赖索位=复校），逐项记录完成状态；
  共享依赖索位若仍被其他活动召回覆盖，撤销本召回时保留其复校完成态。
- **误报撤销**：管理员确认误报后只回滚本召回（索位状态、模型日志、冻结引用），冻结期无召回标记的备注保留；
  其他活动召回不受影响，本批次恢复正常。共享依赖索位若已被**其他未撤销召回（活动或已关闭/已结案）**完成复校，
  撤销时保留该结果；只有没有任何其他召回持有时才回退到最早召回前的基线状态——
  因此「先关闭再撤销」与「先撤销再关闭」对共享索位的终态一致。
- **并发与一致性**：进程内互斥串行 + 全局版本号乐观锁，
  并发召回只成一次，重复提交、过期版本、校验失败一律拒绝且不落库；
  写盘在草稿上进行、临时文件原子改名，提交点失败整体回滚。
- **角色**：页面右上角切换“校准员 / 质量管理员”（请求头 `X-User-Role`，缺省校准员）；
  召回、解冻、撤销仅管理员可执行，越权返回 403。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/state` | 版本号、模型（含索位/批次/依赖）、批次、召回处置全量状态 |
| POST | `/api/batches` | 登记批次 |
| POST | `/api/items/:id/action` | 新增索位（`batchId`、`dependsOn[]`） |
| POST | `/api/batches/:id/recall` | 召回（管理员） |
| POST | `/api/batches/:id/recalls/:rid/checklist/:row` | 完成一项换料/复校 |
| POST | `/api/batches/:id/recalls/:rid/unfreeze` | 全部复校后解冻（管理员） |
| POST | `/api/batches/:id/recalls/:rid/revoke` | 误报撤销（管理员） |
| PATCH | `/api/items/:id` | 状态修改（冻结期 409） |
| POST | `/api/items/:id/logs` | 追加备注 |

所有变更请求需带当前 `version`（取自 `/api/state`），过期返回 `409 version_stale`。

## 测试

```bash
npm test               # node:test：正常、并发、回滚、撤销、持久化、多批次交叉召回、共享索位撤销隔离（20 项）
npm run test:e2e         # 真实 Chromium：单批次处置全流程（含重启持久化）
npm run test:e2e:cross   # 真实 Chromium：双批次交叉召回、单边解冻、重启、末次解冻恢复
npm run test:e2e:revoke  # 真实 Chromium：先关闭一个召回再撤销另一个，共享索位已完成结果不被覆盖
```

浏览器运行库在无 root 环境可解包 Debian deb 后用 `LD_LIBRARY_PATH` 指向，见 `test/e2e.mjs` 开头。
